# 观测价怎么算出来的（2026-11-26）

这份表回答一个问题：**从各站 /api/pricing 抓来的数字，凭什么能当成价格用？**

## 一句话公式

```
USD/百万输入 = model_ratio × 2 × group_ratio
USD/百万输出 = 上面的数 × completion_ratio
```

`model_ratio` 是 new-api / one-api 的模型倍率，约定 1 美元 = 500,000 quota，所以倍率 1 = $2 / 百万 token；`group_ratio` 是分组倍率，同一个站对不同分组给不同折扣。

抓来的数就是这个公式算的，没有别的换算。问题是每个站的倍率表并不是同一把尺子，于是要把 66 份快照分成四类：

| 类别 | 含义 | 能怎么用 | 数量 |
| --- | --- | --- | --- |
| 同口径 | 所有匹配模型都 ≈ 官方 × 1.00 | 直接当价格用 | 26 |
| 整体倍数 | 所有模型乘同一个系数 | 当价格用，但要说明是整站加价/折扣 | 4 |
| 统一价 | 所有模型同价，与型号无关 | 只能记「统一单价」，不能逐模型比 | 10 |
| 口径不一致 | 站内倍率从 1 倍散到几十倍 | 不能用 | 28 |

## 已知的坑

1. **旧代数命名**：`deepseek-chat` / `deepseek-reasoner` / `claude-3-5-sonnet-20241022` 这些老名字，各站的倍率是按老价格表写的，跟现在的官方价不是一回事，所以不参与分类判定。
2. **表达式计费**：少数站的 `billing_mode` 是 `tiered_expr`，`model_ratio` 根本不是单价，是表达式里的系数，这类只能归为「口径不一致」。
3. **分组折扣**：`group_ratio` 小于 1 才是真折扣，但多数分组限定用途（`claude_free`、`gpt生图`、`codex-pro`），取全站最小值会得到假便宜。
4. **`$/M` 前提**：以上都假设站方的倍率表以美元计价（new-api 的默认语义）。如果某站其实按人民币标价，真实价格要再除以 7.1。
