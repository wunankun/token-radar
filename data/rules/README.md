# 站点规则库

每个中转站一个文件，文件名 = `data/sources.json` / `data/providers/` 里的站点 id，例如 `ai-beehears-com.md`。

**这里记「这家站怎么算钱」，不记「某个模型现在多少钱」**。价格走 `data/observed/<id>.json`（自动抓）或 `data/providers/<id>.json`（人工录入）；规则库负责解释这些数字是怎么来的、有哪些坑、哪些分组不能用。

## 什么时候写

- 用户发来截图 / 页面链接 / 卡密说明 → 当场建档或更新
- 抓取脚本怀疑某站口径不对（倍数离谱、统一价、表达式计费）→ 写清它的真实规则
- 每次人工核验一家站，顺手把规则补全

## 必须写的字段

| 字段 | 说明 |
|---|---|
| 站点 | 名称 + 域名 + 结算货币 |
| 来源 | 截图文件名 / 页面 URL / 抓取时间，三者至少一个，**不许编** |
| 账户档位 | 普通用户 / 充值档 / 订阅档（不同档看到的价不一样，这是最大的坑） |
| 分组倍率 | 分组名 → 倍率，标出限用途的（订阅专属、按次、生图、试用） |
| 计费方式 | 按量 / 表达式（tiered_expr）/ 按次；表达式要贴原文 |
| 充值 | 充多少得多少、有没有赠送、赠送是否计入额度 |
| 汇率 | 1 元能买多少美元额度（`/api/status` 的 usd_exchange_rate 或页面公告） |
| 缓存 | 读价折扣、写价倍数、有没有 5 分钟/1 小时两档 |
| 坑 | 实测发现的问题（虚标、掉包、限速、扣费异常） |
| 待核验 | 还不确定的事，写清楚要验什么 |

## 不要写进这里

- 具体模型价格（会变，放 `data/observed/` 或 `data/providers/`）
- 推广链接（放 `data/providers/<id>.json` 的 `affiliate`）
- 未证实的传闻（传闻放「待核验」并注明来源是用户口述）
